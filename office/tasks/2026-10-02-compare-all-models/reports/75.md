### 2. `backend/scripts/diff_comparisons.py`

`--before DIR --after DIR --out docs/MODEL_COMPARISON_<day>.md [--bootstrap 300]`. It reads each run's `predictions.parquet` (forward_1_3d rows only).
- **Three ways**, per arm and slice (all, not San Diego, culture, ddpcr, wet, dry): within-beach AUROC, AUROC, AUCPR, Brier, sensitivity at specificity 0.87.
  - **common**: pairs keyed (beach_id, date, outcome) present in both runs. Each cell shows before → after (Δ [95% CI]), with a beach-cluster bootstrap on the common pairs.
  - **full**: each run on its own pairs, point deltas.
  - **new beaches only**: after pairs whose beach has no pair in before. The before side is empty by definition, so only after values are shown. This is how the brief's "new beaches" slice is realised.
- **Band tables**: realized exceedance rate per risk band (Low < 0.20 ≤ Moderate < 0.30 ≤ High < 0.70 ≤ Very High) per arm, for before and after full pairs.
- **PROMOTION.md verdict**: `promotion_verdict` applies the rule mechanically to the after/full pairs. A challenger passes if both slices (all, not San Diego) have a within-beach AUROC delta CI entirely above 0 and a Brier delta CI entirely below 0, against `logit`. Rule 5 (ties go to the simpler model unless the complex one beats it) is implemented, and every non-`logit` arm is a challenger. The report prints PASS/FAIL per challenger with the deciding CIs. It warns when bootstrap reps are below the 300 that PROMOTION.md requires ("INDICATIVE ONLY"). It also reruns the verdict on common pairs and flags any reversal, as PROMOTION.md's reporting rule requires.
- Sensitivity at specificity 0.87 uses a vectorised `roc_curve` rather than `evaluation.sensitivity_at_specificity`, because the official helper is O(unique·n) and too slow inside a bootstrap. A test pins the two equal.
- It does not import `compare_all_models`, so it loads fast.

### 3. Tests (`backend/tests/test_compare_all_models.py`, +11)
