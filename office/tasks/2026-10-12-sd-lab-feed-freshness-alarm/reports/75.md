## Done

- Implemented `backend/scripts/lab_freshness_check.py`:
  - CLI: `--curated DIR [--today YYYY-MM-DD] [--json-out PATH]`.
  - Analyzes enterococcus sample dates from `observations.parquet` across all merged sources.
  - Determines eligibility: county has >= 20 distinct sample dates in trailing 365 days.
  - Calculates `cadence_days`: median gap between consecutive distinct county sample dates over the trailing 180 days.
  - Calculates `age_days`: days between today and newest sample date.
  - Flags county as `stale` if `age_days > max(14, 3 * cadence_days)`.
  - Merges results into `system_health.json["lab_freshness"]` using `dumps_strict` without dropping other keys.
  - Formats and prints an ASCII table of results per county and exits 0 always.
- Implemented `backend/tests/test_lab_freshness_check.py`:
  - Tests four synthetic county scenarios:
    1. A fresh county (weekly cadence, age 2d <= 21d threshold -> not stale).
    2. A county gone quiet (daily cadence, age 30d > 14d threshold -> stale).
    3. An ineligible sparse county (<20 sample dates in trailing 365d -> not flagged, marked ineligible).
    4. A county with a slow but steady cadence (14d cadence, age 20d <= 42d threshold -> not stale).
  - Tests analyte filtering (enterococcus only; non-enterococcus samples ignored).
  - Tests table formatting.
  - Tests `system_health.json` update preserving existing keys.
- Wired freshness check into `.github/workflows/daily-forecast.yml`:
  - Added step `Check county lab-feed freshness` after observations are generated / serving snapshot built and before the data commit.
