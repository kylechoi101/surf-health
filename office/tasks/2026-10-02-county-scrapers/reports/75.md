## Done

- `fetch_orange_county_samples(client, resolver)` in `backend/scripts/fetch_county_advisories.py`. It reads `https://ocbeachinfo.com/data/` and picks the newest `Orange-County-Beach-Monitoring-Data-*.xlsx` by the date in the filename (`_oc_pick_newest_xlsx`). It downloads the file and parses it with `pd.read_excel(engine="openpyxl")`. `_oc_samples_from_frame` turns the rows into `CountySample`s:
  - Only `ParameterCode == Enterococcus` rows from the last 120 days are kept.
  - `county="Orange"`, `analyte="ENTEROCOCCUS"`, `station_code` and `area` are `StationID`, and `beach_id` comes from `resolver.resolve_by_station_code`.
  - `ND` rows with no `Result` get value 1.0. `exceeds_limit` is `value > 104`. `source_url` is the xlsx URL.
  - Same-station, same-day readings collapse to the worst one, so `persist_samples`' (county, area, date, analyte) dedupe cannot hide an exceedance.
  - It never raises: on failure it logs to stderr and returns 0, so the advisory run is not lost.
- `main()` calls it inside the HTTP client block after the best-effort loop, and respects `--only`.
- `"Orange"` added to `INGEST_COUNTIES` in `backend/app/data/pipeline/county_direct.py`.
- `openpyxl>=3.1.0` added to the base dependencies in `backend/pyproject.toml`. It was already installed in the venv (3.1.5), so I installed nothing. `constraints.txt` only pins the scientific stack, so I did not pin it there.
