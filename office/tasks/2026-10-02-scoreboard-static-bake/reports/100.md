## Deviations

- **Observations are capped at 52 in the bake, 25 in the API.** The contract says 52. `serving.sqlite` keeps 25 (`serving_snapshot.OBSERVATION_LIMIT`), which is outside Allowed files. The parity test requires the baked list's first 25 to equal the API's list and asserts the 52 cap. This is a deliberate difference, and a client reading the static file sees more history than the API would show.
- **Bake-time fields are frozen.** `forecast_age_hours` and `is_stale` in `api/beaches.json[].forecast` are computed at bake time, not request time. Clients should recompute them from `forecast_generated_at`.
- **Null forecast and explain where the API derives or 404s.** `forecast` is `null` for the 354 beaches with no `forecasts` row. The API derives a persistence forecast or 404s there, and the contract's client rule falls back to the route. `explain` is null for the same beaches.
- **`api/health.json` keeps the research sections** (`served_metrics`, `serving_method`, ...) as extra keys, as in phase 75. The API response model drops them. It validates as `SystemHealthResponse`.
- **Nothing else outside the Allowed files.** The `api/` restructure edited only the baker and the new test file.

## Open questions

- **Pre-existing API bug, not touched.** `ServingSnapshotRepository.get_observations` raises `TypeError` (`float(None)`) for 1 of 850 beaches on this snapshot, because a NULL `value` sits in its recent rows. Production would return a 500 there. The baker drops unusable rows, so the static file has data where the API errors. Worth a separate fix in the repository or the snapshot builder.
- **`generated_at` and the 7-day advisory window use bake time.** The API judges them against `serving.sqlite`'s own `generated_at`. The two are about the same moment in the daily workflow. If the bake ever runs long after the snapshot, an advisory near the 7-day edge could differ.
- **Size.** `api/` is 33 MB for 850 beach files, dominated by the per-cell `hourly` payload repeated for every beach in a cell. The PM said this is acceptable. An `hourly/{cell}.json` split would shrink it but changes the contract.
- **`docs/STATIC_DATA_CONTRACT.md`** is outside Allowed files. I did not check that the text matches the final shape, in particular the 52-vs-25 observation cap and the frozen age fields.
