- `backend/app/services/tides.py`: small refactor. The NOAA call moved out of `fetch_tides` into `fetch_station_tides(station_id, name, distance_km, *, hours_ahead, use_cache, _client)`. `fetch_tides` is now a thin wrapper that picks the nearest station and calls it with the old defaults (48 h, cached), so the route behaves as before. The existing `test_tides.py` passes unchanged.
- `backend/app/data/pipeline/cli.py`:
  - New `--with-tides` flag. It reads `beaches.parquet`, maps each beach with coordinates to its station via `nearest_station`, and calls `fetch_station_tides` once per distinct station (96 h ahead, route cache bypassed).
  - Output `tides.parquet` is a long frame with columns `station_id, station_name, station_lat, station_lon, kind, timestamp, height, type`.
    - `kind` is `prediction` or `extremum`.
    - `timestamp` is UTC datetime.
    - `height` is feet MLLW.
    - `type` is `H`/`L` on extrema and null on predictions.
    - The extrema are the ones `tides.py` returns.
  - A station whose fetch fails keeps its still-future rows from the previous `tides.parquet` instead of vanishing. Predictions are deterministic, so those rows stay valid.
  - If every station fails and there is no previous file, nothing is written and the old file is left untouched.
  - The write is atomic (`.tmp` then replace), and a NOAA outage never fails the pipeline.
- `.github/workflows/daily-forecast.yml`: `--with-tides` added to the "Run data pipeline" step (only change).
- `backend/tests/test_pipeline_tides.py` (new, offline fake NOAA client) covers:
  - one call per distinct station (2 calls for 3 beaches mapping to 2 stations)
  - ≥72 h of predictions ahead
  - a request window longer than the route's, with the route cache bypassed
  - carry-over of the previous rows on a station failure
  - an empty frame when everything fails
  - `main()` writing `tides.parquet` end to end
